# H-001: Extend j*(l) past l=20 and characterize e(l) growth

Status: backlog. Opened 2026-07-22.

## Definição do objeto matemático

Para inteiros j, k >= 0, defina o conjunto de inteiros 3-ádicos:

```
R_{j,k} := { sum_{i=0}^{j} 2^{alpha_i} 3^i  :  j+k >= alpha_0 > alpha_1 > ... > alpha_j >= 0 }  subset Z*_3
```

Somas de j+1 potências de 2 multiplicadas por potências de 3 crescentes, com expoentes de 2
estritamente decrescentes e limitados por j+k. O tamanho deste conjunto é exatamente
`C(j+k+1, j+1)` (coeficiente binomial), mas o tamanho da sua imagem módulo 3^l (quantos resíduos
distintos em (Z/3^lZ)* ele cobre) é o que importa.

**Cobertura**: R_{j,k} "cobre" Z*_3 mod 3^l se a imagem de R_{j,k} módulo 3^l contém todas as
`2*3^{l-1}` classes de resíduo invertíveis módulo 3^l.

**Definição central**: `j*(l)` = o menor j tal que `R_{j-1,j}` cobre Z*_3 mod 3^l.

## A conjectura (Wirsching 1998, Weak Covering Conjecture, Conjectura 3.9)

Existe uma função sub-exponencial K(l) > 0 (isto é, `lim_l K(l)*e^{-gamma*l} = 0` para todo
gamma > 0) tal que, para todo j, l: se `|R_{j-1,j}| >= K(l)*3^l` então `R_{j-1,j}` cobre Z*_3
mod 3^l.

Essa conjectura é equivalente (identidade algébrica provada, não analogia) à conjectura beta=1
de Terence Tao (2020) sobre densidade de pré-imagens de Collatz, e implica densidade positiva de
predecessores no problema de Collatz, um dos passos mais importantes rumo à conjectura completa.

número de página está correto nas duas. Não é um problema de conteúdo matemático, só um rótulo
de referência cruzada interno; registrado aqui para não repetir a citação errada num paper
futuro (Rule 11 pede checagem bibliográfica antes de ir para uma bibliografia formal).

Algoritmo original (a reimplementar de forma mais rápida, não copiar em Python):

```
Para cada l, buscar o menor j tal que R_{j-1,j} cobre Z/3^lZ:
  - Processar expoentes candidatos em ordem decrescente
  - Manter, para cada contagem c de termos já escolhidos, o conjunto de somas parciais
    alcançáveis mod 3^l como um bitset
  - Escolher o expoente v na posição c é uma ROTAÇÃO CÍCLICA do bitset por 2^v * 3^c mod 3^l
  - Contagem de bits do bitset final = tamanho da imagem (cobertura)
```

Redução útil já identificada (usar para cortar custo): para j >= l, termos de índice i >= l se
anulam mod 3^l, dando `R_{j-1,j} mod 3^l = 2^{j-l} * R_{l-1,j} mod 3^l`, que reduz o custo de
enumeração de `C(2j,j)` para `C(j+l,l)`.

## Guia técnico inicial

1. Reimplementar em Rust ou C++ usando bitsets nativos (`std::bitset`/`Vec<u64>` com popcount,
   ou GMP se precisar de módulos maiores). Operação central: `bitset_novo = bitset_antigo
   ROTACIONADO por (2^v * 3^c mod 3^l) bits, depois OR com o bitset acumulado`.
2. Paralelismo: considerar múltiplos núcleos (16 disponíveis, ver Section 1 do CLAUDE.md).
   GPU/CUDA não disponível nesta máquina (só gráfico integrado Intel); descartar essa via.
3. Usar a redução já conhecida: `R_{j-1,j} mod 3^l = 2^{j-l}*R_{l-1,j} mod 3^l` para j >= l.
4. Busca de j*(l) por bisseção (cobertura é monótona em j), não varredura linear.
