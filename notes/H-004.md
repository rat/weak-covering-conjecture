## The connection, worked out explicitly

Wirsching's back-tracing vector `s = (s_0,...,s_k)` defines `v_s = T0^{-s_0} o T1^{-1} o ... o
T0^{-s_k}`, composing inverse-halvings (T0^{-1}(x)=2x) and inverse-odd-steps (T1^{-1}(x)=(2x-1)/3,
valid when x==2 mod 3) through the *whole* Collatz graph. L-009's note already cites Wirsching's
own theorem: a length-m admissible vector determines a unique residue class mod 3^m.

This project's `notes/H-001.md` defines `R_{j,k} := {sum_{i=0}^{j} 2^{a_i} 3^i : j+k>=a_0>a_1>
...>a_j>=0}`. `literature/notes/L-003.md` already independently confirmed (2026-07-22, before
this note) that Tao's Syracuse random variable `Syrac(Z/3^n Z) = sum_{m=1}^{n} 3^{n-m}
2^{-(a_m+...+a_n)}`, built from n i.i.d. geometric "waiting times" between successive T1^{-1}
applications in a random inverse-Collatz walk, equals R_{j,k} up to a unit multiple after
reindexing (g_i := b_{n-1}-b_i, strictly decreasing, matching R_{j,k}'s a_i exactly).

**Putting these two together, not independently re-deriving either**: Tao's Syrac construction
*is* a random instance of Wirsching's own back-tracing vector v_s (each geometric variable a_m
is literally a doubling-count s_i between two consecutive T1^{-1} applications). So R_{j,k},
already known to equal Syrac up to a unit multiple, is not merely "similar in spirit" to
Wirsching's back-tracing formalism cited in L-009, it **is** that formalism, specialized to
vectors of a specific length with a specific bound on total doubling weight (R_{j,k}'s
`a_0<=j+k` constraint bounds the total accumulated doubling count). Wirsching's own "residue
mod 3^m" theorem (cited via L-009) is therefore the general statement that this project's
`j*(l)` question is a special case of, not an independent, structurally-different result.

**Numerically checked** (per this project's honesty rules, not left as pure symbolic
assertion): recomputed R_{1,2} directly from the definition (j=1,k=2: terms i=0,1, a_0>a_1>=0,
a_0<=3) and confirmed the image mod 9 is exactly `{1,2,5,7}`, matching the project's existing
verified checkpoint (`notes/H-001.md`'s l=2,j=2 pointwise check) before trusting any of the
above index bookkeeping.

## The precise gap: RESOLVED, 2026-07-28, from the primary source

The book was obtained in full and the relevant chapter (Chapter II Section 2, Chapter V Section
1) read directly; see `literature/notes/L-001.md` for the full citation detail. Wirsching's own
**Corollary & Notation 1.8** (p.127, the exact same numbered result already used for R_{j,k}'s
definition in this project) states, as a proven theorem with an explicit bijection, not a
conjecture or a loose analogy:

```
R_{j,k} = R(F_{j+1,k})
```

an exact set equality between Wirsching's mixed-power-sum set R_{j,k} and the normalized-remainder
image of F_{j+1,k}, feasible back-tracing vectors of length j+1 (i.e. j+2 components). This
resolves the gap flagged below precisely: R_{J-1,J} (this project's notation, J terms) corresponds
to back-tracing vectors of length `(J-1)+1 = J`, i.e. exactly J, matching the target modulus
exponent J with no off-by-one adjustment needed.

**Independently re-verified numerically**, not taken on the book's word: implemented the raw sum
and Wirsching's normalized-remainder formula `R(s)` (Definition 1.4/Lemma 1.7, `alpha_i :=
(l-1-i) + s_0+...+s_{l-1-i}`) for all 6 valid tuples of R_{1,2} (the l=2 case, matching this
project's own verified l=2,j=2 baseline exactly). Every tuple gave an exact match between the raw
sum and R(s), and the resulting set was exactly `{1,2,5,7} mod 9`, the project's known checkpoint.
An initial attempt using a formula transcribed from OCR'd text only matched 4 of 6 cases and was
correctly discarded as unreliable rather than reported as a positive result; the formula above was
confirmed against a rendered image of the actual page before being trusted.

## Second opinion (Gemini, 2026-07-28) and the l=3 stress test it prompted

Per Rule 11b, the researcher got a genuine external second opinion (Gemini, different vendor)
on the R_{j,k}=R(F_{j+1,k}) identity above. Two points came back, both worth recording:

1. **The l=2 check alone is insufficient.** Gemini flagged, correctly, that a length-2 sequence
   has no "middle" element, so an index-reversal or off-by-one bug in the `alpha_i` formula could
   be invisible at l=2 and only surface at l=3 or later. It recommended re-running the same check
   at l=3 (j=2, k=2, modulus 3^3=27) as the minimal real diagnostic before trusting the identity
   generalizes.
2. **Even if correct, the identity gives zero leverage on j*(l)/surjectivity**, independent of
   H-003's specific obstruction. Blunt paraphrase: `R_{j,k}=R(F_{j+1,k})` is a re-encoding of what
   the set *is*, not a statement about how big it is or which residues it hits; "each vector maps
   to a unique residue" says nothing about whether bounded-length vectors *surject* onto all
   residues. This independently confirms (does not add to) what this note's own "What this would
   and would not buy" section already concluded.

**l=3 re-verification, run against point 1** (`literature/papers/131_...pdf`, Chapter V Section 1
pp.125-127, read directly from the primary source, not the L-001.md summary, to avoid propagating
any residual transcription error): recomputed both sides for j=2, k=2 (target modulus 3^3=27).

Raw `R_{2,2}`: the 10 tuples (a_0>a_1>a_2>=0, a_0<=4, C(5,3)=10) give, mod 27:
`{22,4,22,19,10,4,11,2,23,19}` -> unique set `{2,4,10,11,19,22,23}` (7 distinct values, two

`R(F_{3,2})`: the 10 feasible vectors s=(s_0,s_1,s_2,s_3) with l(s)=3, s_0+s_1+s_2+s_3=2 (s_3
doesn't affect R(s), per Definition 1.4's own remark that R doesn't depend on the last
component), evaluated via `alpha_i=(2-i)+s_0+...+s_{2-i}`, `R(s)=2^alpha_0+3*2^alpha_1+

unique set `{2,4,10,11,19,22,23}`.

**Exact match, including which values collide and how many times.** This is a real, independent
stress test (not just a repeat of the l=2 case at a different modulus) and it passes cleanly: the
identity is not an l=2 artifact. Confidence in `R_{j,k}=R(F_{j+1,k})` generalizing is now
substantially higher than after the l=2 check alone.

**A genuinely new piece of context surfaced alongside this** (not previously known to this
project): Wirsching's own "(j,k,l)-locally/globally covering triple" framework (Definitions
1.1-1.13, same chapter) requires vector length strictly less than the target modulus exponent
(`j<l`) throughout. Combined with the identity above, this project's own j*(l) question is
exactly the *degenerate boundary case* `j=l` of Wirsching's own machinery, sitting right where his
recursive covering technique (built for `j<l`) stops applying. This is not a new bound and is not
claimed as one; it is a plausible structural explanation for part of why j*(l) is hard, recorded
here and cross-referenced from `notes/H-003.md` as context for that hypothesis's six blocked
rounds, not a seventh attempt.

## What this would and would not buy the project, if the exact correspondence were confirmed

**Would NOT** directly give a new bound or faster computation method for j*(l): Wirsching's
back-tracing theorem, as cited by Monks et al., states that each admissible vector maps to *a*
unique residue, not that bounded-weight vectors of a given length *surject* onto all residues
mod 3^m (which is exactly j*(l)'s open question, restated, not answered, by this correspondence).

**Would** be a genuine, citable structural unification: it would establish that this project's
central computational object (R_{j,k}, hence j*(l), hence the Weak Covering Conjecture itself)
is not a standalone construction but a direct, provable instance of Wirsching's own general
3-adic back-tracing/Markov-process machinery from the same 1998 book, already known (via the
already-independently-confirmed L-003 identity) to be the same object Tao's Syracuse random
variable and beta=1 conjecture describe. That three-way identification (R_{j,k} = Syrac =
restricted Wirsching back-tracing image) would be worth stating explicitly in a paper, as it
situates this project's specific computation inside a broader, already-published theoretical
framework, which is exactly the kind of citation-maximizing context this project's Rule 10 asks
for, rather than because it advances H-001's numerical goal.
